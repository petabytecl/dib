# Behavior Matrices

This is the initial shared behavior contract matrix for Dib. Package tests
remain the executable truth. This document records the cross-surface hooks that
keep `command/`, `flags/`, and `config/` from drifting as each surface grows.

## Shared Contracts

| Contract | Applies To | Required Behavior | Initial Evidence | Later Hook |
| --- | --- | --- | --- | --- |
| Immutable definitions | `command`, `flags`, `config` | Definitions and derived definitions return new values instead of mutating existing values. Exported APIs do not expose mutable internals. | Story 1.1 `command.NewDefinition` returns a value with unexported fields; Story 3.1 `TestDefinitionDerivationDoesNotMutateOriginalsOrLeakAliases` covers command metadata and children; Story 2.1 `flags.Set.With` returns a derived set without mutating the original. | Add derivation assertions for config keys when those APIs exist. |
| No mutable aliases | `command`, `flags`, `config` | Constructors and derivation methods defensively handle caller-owned slices, maps, readers, environment lookup functions, and config data. Callers must not observe mutation through retained aliases after construction or resolution. | Story 3.1 `TestDefinitionDerivationDoesNotMutateOriginalsOrLeakAliases`, `TestRouteSnapshotsAreDefensiveAndDeterministic`, and `TestRouteResultExposesDefensivePathDefinitions` prove command aliases, child slices, paths, and remaining args are defensive; Story 3.2 `TestRouteResultExposesDefensiveMatchTokens` adds raw match-token snapshot coverage; Story 2.1 tests prove `flags.StringList` defaults, `Set.Definitions`, and default snapshots do not leak caller-observable mutable storage. | Add table tests for each new caller-owned input as config APIs are introduced. |
| Per-run snapshots | `command`, `flags`, `config` | Route, parse, and config resolution snapshots never write back to definitions. A snapshot copies the values it needs and does not depend on live process state, environment variables, readers, lookup functions, or caller-owned mutable inputs after creation. | Story 3.1 `TestRouteSnapshotsAreDefensiveAndDeterministic` proves route snapshots are self-contained; Story 3.2 extends the same test for alias route calls and raw match tokens; Story 2.1 `flags.Set.DefaultSnapshot` tests prove default value state is self-contained and ignores misleading `os.Args` and environment state. | Extend snapshot assertions when config resolution exists. |
| Explicit instances | `command`, `flags`, `config` | Primary APIs accept caller-provided values and instances. They do not read package globals, default singletons, `os.Args`, environment variables, stdin, stdout, or stderr unless that behavior is explicit in the API under test. | `command/contract_test.go` demonstrates explicit command definition construction; Story 3.1 `TestRoutingUsesExplicitInputsAndReturnedValues` proves routing uses supplied args and returned values only; Story 2.1 flags tests demonstrate independent `flags.Set` construction despite misleading process state. | Extend the same pattern to config when that surface adds constructors. |
| Explicit flag name normalization | `flags` | Long flag names match exactly unless a caller supplies a `flags.NameNormalizer`. Normalized sets resolve equivalent long-name spellings to the canonical definition name, reject normalized collisions with typed setup errors, and keep shorthand lookup independent from long-name normalization. | Story 2.2 tests cover exact matching, configured normalization, normalized collision diagnostics, immutable derivation with `WithNormalizer`, and shorthand separation. | Extend parsing tests to reuse the same lookup contract once flag-token parsing exists. |
| Long flag parsing | `flags` | `flags.Set.Parse(args)` accepts caller-supplied arguments, parses long flags in attached and separate value forms, treats boolean presence as true, preserves remaining positional args, records source occurrences, and returns typed diagnostics for unknown, missing, conversion, and duplicate-value failures. | Story 2.3 tests cover `--name=value`, `--name value`, booleans, `--no-*` as an ordinary name, exact and normalized lookup, duplicate single-value flags, minimal `--` terminator behavior, source metadata, defensive snapshots, and redaction-safe parse errors. | Extend the parser matrix for shorthand, short groups, repeat/custom accumulation, and complete boundary behavior in later Epic 2 stories. |
| Short flag parsing | `flags` | `flags.Set.Parse(args)` resolves one-rune shorthand definitions through the set shorthand index, parses required values in `-n value` and `-n=value` forms, treats boolean `-v` presence as true, preserves remaining positional args and `--` protection, records canonical source occurrences, and returns typed diagnostics for unknown shorthand, missing values, conversion failures, and duplicates across long/short spellings. | Story 2.4 tests cover valid short values, boolean presence, positionals around short flags, unknown shorthand, missing values, invalid conversions, duplicate values, normalized long-name independence, `--` protection, canonical occurrence metadata, and redaction-safe shorthand conversion errors. | Add grouped shorthand behavior, optional group values, full boundary matrices, repeated/custom accumulation proof, and fuzz/property tests in later Epic 2 stories. |
| Grouped shorthand parsing | `flags` | Single-dash tokens with multiple shorthand members and no `=` parse as shorthand groups. Boolean members are applied left to right; a final required-value member may consume an attached suffix such as `-an10` or the next argument in `-an 10`; a no-option default is applied when a grouped member is present without an explicit value; a non-final required-value member without a no-option default returns `flags.ErrInvalidGroup`. | Story 2.5 tests cover boolean groups, final attached and separate values, no-option defaults, invalid non-final required members, unknown members, invalid conversions, duplicate values within and across grouped/long spellings, partial-failure behavior, `--` protection, source occurrence metadata, and deterministic grouped-input fuzz/property checks. | Add complete repeated/custom accumulation, full parse boundary behavior, final parser fuzz matrices, compatibility tables, and release evidence in later Epic 2 and Epic 5 stories. |
| Repeated and custom values | `flags` | Repeated occurrences accumulate only for definitions configured with `flags.Repeatable()`, preserving command-line order across long, short, grouped final shorthand, and no-option default forms. `ValueState.Values()` exposes effective values; `ValueState.Occurrences()` exposes one provenance record per explicit CLI occurrence. `KindStringList` parser results flatten into effective values while retaining one occurrence per CLI token. Single-value duplicates are rejected before converting the second value. Custom parsers store validated, defensively copied values and preserve non-sensitive parser causes through Go error inspection; sensitive custom failures redact raw values and caller parser causes. | Story 2.6 tests cover mixed-spelling accumulation, no-option repeated accumulation, duplicate rejection before conversion across long, short, grouped, normalized, and mixed spellings, scalar custom parser success, custom `KindStringList` flattening, mismatched custom result kinds, non-sensitive parser wrapping, sensitive redaction, and reusable parse runs with mutable parser results. | Add full parse boundary behavior, final parser fuzz matrices, compatibility tables, migration examples, and release evidence in later Epic 2 and Epic 5 stories. |
| Parse boundaries | `flags` | Positional arguments interspersed with flags accumulate in `RemainingArgs()` in their relative order. The `--` terminator stops flag parsing; every token after `--` is preserved verbatim in `RemainingArgs()` even if it looks like a flag. Help requests (`--help` or `-h` when not registered by the caller) return a typed `ErrHelpRequest` diagnostic for caller-controlled rendering and exit policy; no runtime path calls `os.Exit`. Parse failures (unknown flag, missing value, invalid value, invalid group, duplicate) return a typed `*flags.ParseError` and a zero-value `Snapshot` so callers cannot accidentally use partial state. | Story 2.7 tests cover positional-only args, flags-only args, interleaved positionals and flags, multiple positionals between flags, `--` alone, `--` followed by flag-like tokens, `--` as the first arg, `--` after parsed flags, passthrough args after `--`, each parse-failure category with `errors.Is`/`errors.As` typed assertions, zero-value snapshot on failure, registered `--help`/`-h` parsing normally, and a fuzz harness (`FuzzParseBoundary`) with clean-room seed corpus verifying no panic and boundary invariants. | Add full parser fuzz matrix proof, compatibility tables, and release evidence in Story 2.8 and Epic 5 stories. |
| Public error inspection | `command`, `flags`, `config` | Errors that callers need to handle programmatically are typed or sentinel errors inspectable with `errors.Is` or `errors.As`. Error strings are diagnostics, not the programmatic contract. | Story 1.1 uses `errors.As` for `*command.NameError`; Story 3.1 `TestRouteUnknownCommandErrorsAreInspectable` uses `errors.Is(command.ErrUnknownCommand)` and `errors.As` with `*command.UnknownCommandError`; Story 3.2 `TestDefinitionRejectsInvalidAliases`, `TestDefinitionRejectsAliasTokenCollisions`, `TestTokenConflictErrorParentPathIsDefensive`, and `TestAliasErrorParentPathIsDefensive` cover alias setup diagnostics; Story 2.1 uses sentinel errors with `*flags.DefinitionError` and `*flags.ValueError`. | Add typed error assertions for config resolution. |
| Diagnostic vocabulary | `command`, `flags`, `config` | Human-facing diagnostics identify the package surface, command/flag/key name when applicable, typed category, source label when applicable, and redaction status. | `docs/diagnostics-and-errors.md` defines the vocabulary shape. | Add source report and rendered diagnostic tests when diagnostics are implemented. |
| Source labels | `config` | Config provenance uses exactly `default`, `explicit setter`, `flag binding`, `env`, and `JSON`. | `docs/diagnostics-and-errors.md` fixes the vocabulary before config resolution exists. | Add provenance matrix tests in config precedence stories. |
| Redaction corpus | `command`, `flags`, `config` | The fake sensitive values are exactly `dib_fake_secret_value`, `dib_fake_password_value`, and `dib_fake_token_value`. Raw sensitive values must not appear in public diagnostics once redaction behavior exists. | `docs/diagnostics-and-errors.md` fixes the corpus and redaction scope; Story 2.1 proves sensitive flag conversion errors omit `dib_fake_secret_value`. | Add redaction assertions for debug strings, examples, and source reports as those surfaces exist. |

## Flag Parser Evidence Map

This section provides the Epic 2 parser evidence map with FR traceability and
executable test evidence. Each row names the behavior area, its functional
requirement IDs, the expected behavior, and the exact test or fuzz functions
that prove it. Status `current` means evidence exists in the repository today;
`later` means the behavior area depends on command routing, config binding, or
release-candidate validation outside Epic 2 scope.

This document does not claim source compatibility with Go `flag`, pflag, Cobra,
or Viper. Behavior-scoped familiarity with those APIs informed the design, but
no source, tests, comments, examples, fixtures, internal names, or file
organization were copied or adapted from them.

## Current Scope Boundaries

This matrix tracks the Epic 2 flag parser surface and the initial Epic 3 command
routing surface. The parser evidence map above is complete for the behavior
areas implemented in Stories 2.1 through 2.8, and the command rows cover Story
3.1 root and nested routing, Story 3.2 alias routing and validation, and Story
3.3 command local/inherited flag composition evidence.

The matrix does not claim that command routing, config precedence, source
reports, redaction rendering, compatibility tables, migration examples, or
release-candidate evidence are complete today. Help rendering, handler
execution, and lifecycle ownership remain marked `later` and are owned by later
Epic 3 stories.
