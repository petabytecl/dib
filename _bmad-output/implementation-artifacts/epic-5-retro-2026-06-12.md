## Key Insights

1. Evidence docs need their own tests.
   The highest-risk artifacts in Epic 5 were not runtime packages; they were trust documents that could overclaim or drift from code. Docs tests caught and now guard that surface.

2. "Current evidence" and "approved release" must stay separate.
   Story 5.4 can record repeatable local gates and release-candidate evidence, but the final tag decision remains human release review.

3. Compatibility clarity is strongest when framed as boundaries.
   The table works because it names supported behavior, narrowed behavior, omissions, intentional differences, reasons, and Dib-owned evidence.

4. Migration examples should remain tests, not prose-only snippets.
   Executable examples kept the adopter path honest and helped prove that the docs did not require ambient process state or framework-shaped code.

5. Final doc verification should include commit identity checks.
   Release evidence is tied to exact commits, so the recorded commit must refer to the commit that actually contains the evidence package.
